Use "UNCERTAIN" only if you genuinely cannot determine whether the vulnerable code path is reachable.

If your verdict is YES, you must also submit a proof of concept in the `poc` field: the concrete command-line arguments that make the program actually exhibit the vulnerability when it is run, as a single shell-style argument string containing exactly what would follow the program name (for a program invoked as `prog <input> <flags>`, the string holds `<input> <flags>`). The arguments must trigger the vulnerable behaviour, not merely reach the vulnerable code: construct an input that makes the flaw show itself (a crashing size, an escaping path, an injected command, or whatever the flaw needs). If you cannot produce working arguments, that is a reason to lower your confidence or answer UNCERTAIN, not to submit a guess. Omit the `poc` field when your verdict is NO or UNCERTAIN.
